## Jak proběhlo ověření

Před zápisem byl přečten uživatelův katalog i specifikace KEY-65. Obsah níže byl otevřen přes webový nástroj na konkrétních veřejných primárních stránkách; pracovalo se s celou extrahovanou stránkou a jejími nadpisy, ne jen se snippetem vyhledávače. Nástroj někdy dodává indexovanou verzi a datum crawl se liší od data kontroly. `checkedAt=2026-10-28` proto označuje vlastní kontrolu přečteného obsahu, není tvrzením o nové revizi origin serveru ani o novém datu právní účinnosti. U SHerny nástroj uváděl starší crawl některých podstránek; bez doloženého published/updated data zůstávají obě pole null.

Přijaté provozní podklady mají výlučnou administrativní hranici `reviewAfter=2026-11-04` v UTC. Provozní dostupnost se nepotvrzuje v reálném čase. Zdrojové HTML/PDF ani osobní záznamy nejsou zkopírované do repozitáře; ukládají se stručné vlastní parafráze a dohledatelné locatory. Žádné přihlášení, formulářová operace, placené API, scheduler či crawler nebyly použity.

## Retrieval případy a předání runtime

`retrieval-cases.json` obsahuje 13 přirozených českých otázek a konkrétní očekávané nové chunk IDs. Každý případ zakazuje oba archivní source IDs. Navíc musí runtime ověřit návaznosti: „Kde vyvolám film?“ → „Jak se tam dostanu?“ zůstane photography; „Chci tisknout model“ → „A kolik to stojí?“ zůstane printing bez ceny z obecného SH členství či SÚZ kolejného; „Jak rezervuji SHernu?“ → „Jaká jsou pravidla?“ zůstane game-room.

Všechny nové URL a jejich obsah jsou veřejné, ale jako citace vyžadují přesný ověřený host `sherna.siliconhill.cz` vedle existující wiki domény. Metadata i corpus vlastní tento task, runtime/shared allowlist a celkové indexové testy vlastní přidělený runtime agent. Data se publikovala jedním dokončeným zápisem každého souboru před oznámením ostatním agentům.
