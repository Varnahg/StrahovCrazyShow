# Native rendering maintenance audit — 2026-10-11

Implemented only in `client/cinematic.ts`, `client/surface-pack.ts`, `client/labels.ts` and the new on-demand `client/render-cost.ts`. Geometry, model textures, source positions, high-detail assets, quality limits, LOD distances, physics and Game controls are unchanged.

## Proven work removed

- Babylon 9.30.0 `Rendering/objectRenderer.js` dispatches an explicit render list without a frustum test. The former Cinematic list supplied all eligible meshes within 85 m to a 72 m wide solar shadow camera. `getCustomRenderList` now rejects only an AABB completely outside the actual, current light view/projection. It executes after the ShadowGenerator updates that matrix and before readiness/draw dispatch. Boxes crossing a plane remain. The margin is 0.05 m for shadow bias plus 0.5 m for wind-deformed geometry. Current clean-tree displacement is bounded below 0.1 m by the existing 16 m/s clamp and shader coefficients.
- Inactive LODs remain broad-phase candidates, but the draw callback checks their current enabled/visible state. A newly enabled LOD immediately contributes without waiting 0.4 s; hidden LODs never enter the returned draw list. Quality changes immediately rebuild candidates and rebind the callback if the shadow map is recreated. The original 85 m broad-phase boundary and all shadow-quality settings remain.
- During night, the solar light's shadow pass is disabled and its broad-phase list is not repeatedly rebuilt. Dawn refreshes it immediately. Sky reflections, moon illumination and warm window masks remain active.
- SurfacePack subscribes to added/removed meshes and changed material assignments. After its initial pass, an unchanged world is no longer scanned every 0.5 s. Shared Standard/MultiMaterial references still produce shared PBR materials; a late load or reassignment is converted on the next maintenance interval. Rain/quality uniforms are changed when their input changes or a new conversion appears, instead of rewriting every converted material on every frame. Cleanup unregisters observers and restores originals.
- B6 Fresnel configuration processes new material notifications once rather than rescanning all materials every 0.4 s. Name labels skip matrix projection for out-of-range landmarks and off-floor room signs. Existing distances, hysteresis, budgets, four LOS casts/frame and the rendered-camera projection remain.

Babylon's material and receiveShadows setters already have equality guards. Reassigning an identical material was not a proven shader-recompilation bug. ObjectRenderer also rejects disabled meshes before drawing: hidden LODs were not a proven GPU draw bug. The confirmed shadow problem was geometry entirely outside the shadow camera, not merely outside the player's main camera. ArtLighting already limits active local lamps to two on medium/high and none on low.

## Evidence and reproducibility

`pnpm exec tsx --test tests/cinematic.test.ts tests/render-maintenance.test.ts tests/labels.test.ts`: **20/20 PASS**. The final 0.05 m bias margin was followed by another **5/5 PASS** run of render-maintenance tests. Targeted strict TypeScript compilation of these modules, tests and profiler script passed. Tests exercise asynchronous materials, shared MultiMaterial restoration, no steady-state full scan, dry/wet transitions, quality/map resize, exact Babylon light matrices, crossing bounds, wind margin, immediate LOD switches, night/dawn, observer cleanup and unchanged label/LOS budgets. NullEngine's unsupported raw-cubemap GPU resource is explicitly stubbed in CPU tests; no GPU behavior or frame rate is inferred from those tests.

Run `pnpm exec tsx scripts/profile-native-maintenance.ts` for the inspectable construction/counter report [native-maintenance-counters.json](./evidence/native-maintenance-counters.json). It loads the original tree and compact-car GLB geometry, actual native DMR terrain, source streets and parking surfaces. Trees use an explicitly labelled untextured surrogate material because image decoding is excluded; source GLB material/texture counts are reported separately. It does **not** construct architecture, B6, avatars, grass or HUD. Inputs and script are SHA-256 recorded before/after.

The actual original tree GLB is 183,087,208 bytes, with 657 mesh primitives, **three shared materials**, nine textures and 1,963,056 / 654,724 / 256,428 triangles in LOD0/1/2. There is no evidence of hundreds of unique tree materials/shaders.

The partial construction has 1,031 registered meshes, 558 enabled/visible geometry meshes, 472 hidden geometry meshes, 686 distinct shared geometries and 598,024 enabled potential triangles. It includes 37 registered lights, only one enabled. Registered and referenced material counts are reported separately because asset-container materials may remain referenced without being present in `scene.materials`; assignment groups are not labelled shader variants.

For canonical spawn and the browser diagnostic's real solar instant, the partial geometry shadow list drops from **336 active 85 m candidates to 257 submitted casters**, and from **82,501 to 63,726 potential shadow triangles**. These are structural work counts, not measured GPU draw calls or FPS. During 600 simulated steady-state updates, SurfacePack performs **zero further mesh visits and zero material updates**. Initial conversions remain real source-surface conversions; the report records their count. The final report includes the construction CPU duration but this is not a rendered-frame duration.

The supplied whole-game [native-scene-diagnostic.json](./evidence/native-scene-diagnostic.json) is retained as a **provisional pre-change diagnostic**: 1,280×720, low quality, one actual avatar, Intel UHD 630, 3,141 geometry meshes, 322 draw calls, 17.7 FPS, p95 89.1 ms, p99 96.3 ms; its single last-frame CPU/GPU values are 63.6/19.44 ms. It was not source-frozen and is not a final benchmark or a before/after comparison. These fixes cannot honestly be claimed to solve the entire CPU bottleneck or achieve 60 FPS.

Root integrated `captureRenderCostInventory(scene)`, Cinematic/SurfacePack/vegetation counters and separate simulation/world/avatar-camera/environment/render/label timings into the real Game benchmark. The next source-frozen whole-game run must identify remaining CPU work and measure GPU results with real sessions/HUD. No browser, main server, GPU preference or user setting was modified by this audit; no full suite/build was run by this subagent.
