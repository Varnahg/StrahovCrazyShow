# Native regular-instance buffer identity guard

21 October2026, direct implementation leaf `webgpu-completion-native-instance-buffer-20261021`, baseline77efa9d1. Owner `webgpu-completion-01a15a3e-instance-native-v1`. No recursive BMAD, installation, shared node_modules mutation, Game/UI change, build, server, GPU or commit.

## Research and decision before implementation

Pinned Babylon9.30 native chain: Mesh.render selects batch/material, readiness, Material._preBind→engine.enableEffect and material binding, then _processRendering→_renderWithInstances→_updateInstancedBuffers. That update replaces current/previous matrix Buffer and world*/previousWorld* views, then calls Geometry._bind→engine.bindBuffers→engine._draw. Geometry._notifyUpdate is not called by changing these override maps. Native _invalidateInstanceVertexArrayObject only invalidates GL VAOs. NCM _draw reuses fastBundle while DrawContext/material remain clean, before pipeline/vertex binding. Pipeline layout hashes describe format, not the baked GPU handle; getRenderPipeline updates vertex inputs even on a cache hit, but the early bundle path skips it. Material, shader or UBO identity changes can incidentally invalidate a bundle; none is guaranteed by matrix replacement.

The exact prior successful inline source is preserved in `inline-red-repro.mjs`, before the candidate patch is written. It uses two actual Mesh.render calls, native base Material/Geometry/InstancedMesh/buffer manager/pipeline+bindgroup caches. Fake inputs are an already prepared Effect, device/pipeline/encoder terminal IO and raster state application. Cold draw records current+previous2048B;40real instances grow them to4096B. Original parent Buffer.dispose moves default references1→0; deferred sweep destroys both old raw handles. The second draw nevertheless reuses the first bundle, which contains the old raw handles and no new current handle. No seeded bundle, manual dirty reset or extra release. Earlier development attempts only corrected terminal fixture currentSampleCount getter assignment and missing fakeEffect.getEngine. This is an independent native CPU counterexample, not Standard/PBR/fullGame GPU verification and not attribution of actual buffer37326.

The original actual NCM fault37326/2048 remains owner-unknown; root's frozen source5/helpera5/v6 GPU session is not modified. [MDN GPUQueue.submit validation](https://developer.mozilla.org/en-US/docs/Web/API/GPUQueue/submit#validation), verified by the coordinator, requires encoded resources to remain available and not destroyed. No claim that the full W3C submit document was read. Pinned source is the main mechanism evidence. PR18238's SelectionOutlineLayer fix already exists; the app does not use that layer and its outside-draw resetDrawCache lifecycle cannot be copied inside this active draw.

| Variant | Cache, lifecycle, visual/performance risk | Decision |
| --- | --- | --- |
| Dispose world VertexBuffer views only | Views do not own the parent Buffer; no bundle invalidation | Insufficient |
| mesh.resetDrawCache inside update | Disposes active DrawContext after preBind/bind; buffers becomes undefined, UBO/indirect ownership released, effect churn | Reject |
| active DrawContext.reset | Clears already bound Mesh/Material buffers and owner UBO slots | Reject |
| Clear only current bundle once in growth branch | Other pass/submesh/shadow contexts can replay old handles later | Insufficient |
| Per-active DrawContext current+previous actual DataBuffer IDs before every real regular-instance draw | Two scalar comparisons, no per-draw allocation/scans; lazy covers each future context/pass/shadow replay, preserves binding/indirect lifetime | Selected non-pulling NCM scope |
| Generic engine vertex/index/attribute identity guard | Broader coverage including custom/thin/geometry but broader hot-path scan/cache semantics | Separate possible task |
| Delay destroy/add fence | Retains memory and can mask indefinitely repeated stale bundle | Reject |

The guard belongs inside existing effect+fillMode real-draw branch, after native buffer update and before bind/draw. It must cover first current, same-capacity first previous, missing/disposed/null identities and ordinary growth. Only fastBundle is invalidated, preserving UBO bindings, indirect buffer and material/effect/context identity. WebGL and WebGPU CM bypass; useVertexPulling=true explicitly bypasses because its separate setVertexPulling storage refresh problem is outside this app contract. No general custom/thin/index/geometry fix, new GPU call, readiness, fence or timeout is promised. No performance improvement is inferred from CPU tests.
