## Alternatives and selected correction before runtime changes

| Variant | Behavior, appearance, work, cache and lifecycle costs | Decision |
| --- | --- | --- |
| Change callers to standalone or force all custom material readiness | Adds shadow-pass variants and changes normal material/caller behavior; does not restore general wrapper alias API | Reject |
| Restore global source/invalidation | Restores alias API but reintroduces actual independent shadow eviction/cache miss | Reject |
| Add fallback only in _makeEffect | Binding may choose a different source; target retirement can dispose the source-owning mainDrawWrapper; leaks or wrong binding remain | Insufficient |
| Shared private NOTIFIED-source resolver, explicit source owner and target alias | Known requested canonical always wins, even pending/disposed; absent requested can borrow one live exact notified source; no new Effect history/cache/GPU work | Select |

Resolver rejects invalid/retired targets. If the requested pass exists in the canonical map, it returns exactly that tuple; a pending/disposed base fails the existing ready guard without fallback. Only absent requested may borrow latest notified tuple if it still exactly matches its canonical source slot and the source pass is live. engine.currentRenderPassId is not substituted for source provenance: public alias calls may run current0/request2. Use the same resolver for binding and readiness. Canonical Map order follows actual notification order, so retirement can choose the last remaining legitimate source without a historical variants/tombstone cache.

Every derived entry still owns exactly one acquire, keyed by submesh/generator/SOURCE pass. Its mainDrawWrapper lives at drawWrapper[sourcePass]; a distinct target gets only an alias context. Target-only release disposes aliases; source release retires its entry and every alias. Promotion of a target to its own canonical pass detaches its previous foreign alias and creates an independent entry. Reentrant create must still own the entry and exact source tuple, and target must remain live. A changed fallback selection releases the acquire and returns null; unrelated main notification cannot disturb a known canonical shadow source. No shader recipe/token tuple/Effect-history ownership is changed.

## Implemented result and refactoring

The canonical live-pass Map now stores the already notified [Effect,sourcePass] tuple and the legacy latest facade references that same tuple. Re-notifying the same Effect reuses its tuple but moves that live slot to the latest notification order. Both resolver calls return existing records without new read-time arrays; repeated identity assertions cover canonical and alias reads. This is one representation of each live notification, not another resource/history cache. The shader recipe and exact source/ABI token helper remain byte-exact against source11.

Known requested canonical records always win; their pending/disposed state cannot fall back to an unrelated ready Effect. Absent requested passes may borrow only the precise still-live notified source record. Binding and readiness share this selection. Main depth context ownership is at the source slot; requested aliases own contexts only. Post-create selection must still be the identical tuple, and both source and requested target must be live. Promotion/retirement/reentrant selection and latest remaining notification behavior are exercised with real native cache refs. Original nonstandalone generator entries retain their acquire until source/mesh/wrapper retirement; retiring or resizing an alias RTT retires its context, not the still-live source entry. No new generator-dispose API or Effect-history policy is introduced.

Original alias2 without synthetic notify2 and original guarded freshness notify0→ready9 are restored. Existing two-canonical-pass tests remain distinct. Twelve new cases include actual ShaderMaterial main readiness followed by native ShadowGenerator RTT readiness with the exact production remaps, current0/request2, pending/disposed known requested, binding source drift, alias promotion, actual notification order, two actual RTTs, and five reentrant selection/promotion/release cases.
