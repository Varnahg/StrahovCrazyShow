## Primary chain and actual gap

On21 October2026 the [GPUDevice.destroy documentation](https://developer.mozilla.org/en-US/docs/Web/API/GPUDevice/destroy) and [GPUDevice.lost contract](https://developer.mozilla.org/en-US/docs/Web/API/GPUDevice/lost) were read directly. Destroy affects that device and its resources; native loss is delivered through the existing Promise. Calling destroy is not evidence that product recovery succeeded. It does not justify OS/driver/global GPU actions.

Current `client/webgpu-validation.ts:watchWebGpuValidation` attaches to the initialized engine's device and its original lost Promise, guards active/device identity, then delivers actual loss to RenderHealth. UI/Room cleanup/re-entry remain owned by the product. This helper must not wrap those paths, emit a synthetic health error or manufacture a successful recovery receipt.

No document.hidden mutation, synthetic event, browser driver or management of other tabs is involved.

## Variants, choice and costs

1. Synthetic RenderHealth error: would test only downstream code and not native device loss; rejected.
2. OS/global GPU/driver crash: affects unrelated programs and provides unnecessary scope; rejected.
3. Existing own-device destroy from an explicit diagnostic click: selected. No device/queue/readiness/render method is added before the action, no production patch or global/per-frame hook is required.
4. Programmatic focus/visibility spoof or polling: does not prove the actual browser lifecycle; rejected. A safe native anchor is selected, without claiming its eventual selection/visibility result.

The new canonical default-off `--lifecycle-controls` flag is part of helper/build/browser/receipt identity. Query parameters cannot activate it. Plain builds install no lifecycle owner and do not read Game/device state through the new helper. Enabled builds are diagnostic. The small owner captures exact Game/Scene/engine/device/health renderer+generation and abort ownership; click revalidates current owner, ready/valid/no errors/pending0/no startup lease/preparation/benchmark, exact method and device identity. A WeakSet prevents a second destroy of the same device without retaining it. Original receiver, synchronous return and even falsy throw are preserved; observer/receipt faults cannot replace them. Dispose is idempotent, removes only owned listeners/observer and clears strong Game/device references. No method descriptor is installed/restored.

Action evidence is a bounded scalar addition to the existing state receipt: an attempted original call and returned/threw outcome, not a lost/recovered assertion. The original asynchronous monitor and product error/Room/UI flow must be practically checked after the action. Immutable failed-transfer queues and receipts retain their current ownership. New source+seal means a fresh independent build; frozenv6/a5b3 and all played builds are untouched.
