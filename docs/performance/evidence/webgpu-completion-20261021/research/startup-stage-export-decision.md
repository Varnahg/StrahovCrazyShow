# Bounded startup stage evidence for source15

24 October2026. This is a diagnostic helper change, not a game optimization. The read-only [source14 analysis](source14-startup-gap-analysis.json) binds both original receipts/server logs: Low plus first Medium accounts for70.79%/69.94% elapsed; second Medium has871.4ms margin to the original30s budget. Both full lighting-preparation records were lost to recordSize1. Existing V16 summary deliberately captures qualities only, so concrete76stage CPU/check/render/restart/rafGap cannot be reconstructed.

Primary inputs: pinned client/light-preparation.ts, render-quality-preparation.ts and Game.prepareLighting; V16 startup-observer/qa-overlay/receipt sources. Independent performance audit inspected the same inputs. Cumulative828shaderPreparation/1656modules/1267async+25sync include construction/assets and are not light-only delta. Async completion sums overlap and are not GPU execution. Concrete stage causes and fence versus validation attribution remain unmeasured.

| Option | Cost, risks, lifecycle and measurement effect | Decision |
| --- | --- | --- |
| Keep quality-only evidence | No change; cannot rank stages or attribute CPU in the next run | Insufficient for the requested analysis |
| Raise production logger32KiB cap | Changes general recorder memory/traffic/lifecycle and only moves the size boundary | Not selected |
| New per-stage wrappers/polling/GPU/readiness probes | Adds timing/control-flow interference and ownership restoration | Not needed for existing result fields |
| Project bounded scalars once in the existing fulfilled observer, export in the same startup receipt | Reuses the original result and single native.then; finite one-time CPU/allocation after original preparation resolves; no original Promise/value/resource retention or rendering calls | Selected |

Create an isolated V17 helper by byte-copying the existing36 V16 files, changing only helper code/tests/docs. V16/helper36, source14 and all production sources/assets/native inputs stay unchanged. Reuse observePreparationResult's fulfilled handler for projectPreparationStages(value), expose stagesSnapshot(), and include preparationStages only in the top-level startup raw. No second observer/wrapper/then/timer. Dispose restores only its own descriptor and drops live owner/resource references while retaining scalar evidence.

Projection uses only own data descriptors, never getters/arbitrary object serialization. Rows contain index/passIndex/passQuality, closed19stage enum, elapsed/active/paused, tickCount/checks/renders/restarts, existing cpu.apply/checkBatch/render.{calls,totalMs,maxMs}, rafGap.{count,totalMs,maxMs}, fixed restart-reason whitelist. Numeric invalidity is null plus flags, not clamped/rounded. Map passIndex cumulatively from at most16 quality rows/stageCount; validate total and original stage.passQuality, preserving repeated Medium and partial/failure cases explicitly. passQuality names the preparation pass, not a guarantee that restore rendered that quality.

Limit304 rows (19x16) and256KiB projected JSON. Preserve original count, capturedCount, truncation, invalid fields and mapping validity; cap overflow keeps an explicit prefix. Never enumerate arbitrary restart strings: only14 current Game.revisionKeys plus revision-length, explicit whitelist coverage; generic revision-N is not claimed complete. Existing receipts399351/390983bytes plus conservative76x2KiB are below the existing2MiB cap. Receipt validation must check a present projection strictly and allow it only for startup. Original V16 receipt format stays accepted; unavailable/rejected/partial evidence remains explicit.

Tests must cover actual observer integration/Promise identity+one side reaction, scalar-only bounded projection, repeated-quality mapping,304/16/byte caps, sparse/getter/proxy/nonfinite/exotic data, failures/rejections/dispose/stale owners and receipt acceptance/rejection.
