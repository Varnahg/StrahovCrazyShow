# QA serializer schema proof: preimplementation hypotheses

1. Earlier parser-only B/C still validated/Set/sorted every complete block and did not improve whole warm render. This experiment instead caches only immutable names/permutation validity per weak defines key.
2. The actual mutable `_keys.length`, `_keys[index]`, property-read and inline-format/coercion sequence must remain exact. Per-call fragments may be emitted in cached name order only after all reads complete. No values/fragments/results/engine/device are retained in metadata.
3. Each call validates the complete observed names sequence; a mismatch, unsafe value/name, duplicate, dynamic key or limit uses unchanged canonicalResult on exact raw text. One maximum1024-name/32768-combined-name-unit schema per live key; no cross-engine cache or API/callsite changes.
4. Reentrance requires per-call scratch and immutable local schema; cache publication only after a successful full fallback. Global intrinsic monkeypatch behavior inside the canonicalizer is not an optimization contract, as with the earlier memo, but property getters/coercion/order/throws are.
5. New module state initializes before exported class binding, and a readiness flag prevents fastpath during partial module evaluation. Existing empty cyclic calls remain valid; nonempty early canonicalizer behavior is preserved.
6. Numeric strings require a true full match, including rejection of final newline; whole-block multiline injection still reaches the old canonicalizer. Symbol/object property keys format in the original inline expressions before fallback.
7. Dictionary fragments with null prototype avoid inherited numeric setters between getters. Common hits avoid per-call schema copying, regex names, Set and sort; correctness takes precedence over speed.
8. Allocation/sequence/value checks may outweigh savings. Evaluate current actual PBR/Standard whole warm switches against A and existing memo without wrapping memo toString; report negative outcome if whole-chain benefit is absent. No GPU/FPS or acceptance claim follows from Node timing.

Lifecycle: derived names metadata belongs to the weak defines key and is replaced, not accumulated. Bounds limit per-key logical metadata, not total heap/GC. Shader resources, defines values, getters and public descriptors are not cached or altered. Parent owns current55-state parity/full build/browser acceptance.

Dynamic accessors/proxies still execute every original read. A hit means that the *entire observed sequence* matched an immutable previously validated schema, not that `_keys` identity or length was trusted. Changes fall back for that call and may publish a new immutable schema only after successful canonicalization. A key getter which changes identities but produces exactly the same observed sequence has no read/throw bypass. Per-call scratch is ephemeral and is not retained by WeakMap; generic extremely large key arrays can allocate more temporary fragment storage than the old concatenating loop. The bounds here are the requested retained metadata bounds, not a universal temporary heap guarantee.
