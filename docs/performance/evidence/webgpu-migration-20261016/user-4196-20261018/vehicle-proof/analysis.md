# Low vehicle light proof

Read-only source research: Game's actual 13-stage single-quality preparation toggles the player torch while car visibility stays disabled. VehicleLighting low has shadowEnabled=false; the player torch keeps true. Pinned PrepareDefinesForLight makes this a distinct key only for an actual shadow receiver with a nonempty shadow render list. Some material Effect IDs in user seq1291 were already used earlier, so 387 changes are not 387 new programs. User seq1264 has a 193.5ms CPU burst/3programs before the600ms gap; seq1291 has215.2ms/5programs before903ms. GPU/backpressure causality is not established.

Compare baseline13 -> actual car0/1POINT against baseline13 -> actual car warm0/1 -> restore -> car0/1, and against temporary torch shadowOFF. Prefer the actual car controller for a possible runtime candidate because it owns the real light budget/mode/pose; shadowOFF is only a controlled shader-key alternative. No cache/hook is needed to test these missing first variants.

The small fixture runs extracted unchanged Game.prepareLightingVariants/isMeshReadyForCamera/updateRenderEnvironment, actual prepareLightVariants, applyArtLighting, PlayerFlashlight, VehicleLighting, GltfLightBudget and StableLightState on pinned NullEngine. Only the Game-side WebGPU stage-selection flag/scheduler, browser IO, sky texture IO, and unrelated world/avatar presentation are bounded adapters. Actual scene mesh/effect readiness and render dispatch are not mocked. No actual car GLB, full avatar animation, world streaming, WGSL/GPU pipeline, pixel or performance claim. ReceiveShadows=false and medium are controls; exact defines and Effect objects distinguish reuse from compilation. Actor/presentation DTOs and transform restoration are checked.

First run preserved: placing the nonreceiver control in the SAME engine prewarmed matching engine-wide keys. Per-receiver new Effect did not mean a new program. Final fixture isolates the control in another engine and records both levels of reuse. The low PBR receiver has one actual new program per POINT count; the basic Standard receiver can reuse an engine-cached program already prepared by another nonreceiving Standard draw. This is an observed limitation, not a failed mechanism hidden by changing the claim.

NullEngine uses its normal regular-instance fallback (actual visible instance batches, INSTANCES not enabled) and falls PCF back to SHADOWPOISSON. Thus exact observed removal is SHADOW0/SHADOWPOISSON0/SHADOWS. This proves the shadowed/unshadowed frontend family distinction, not production hardware-instanced WGSL identities. Actual car0/1 warmup and temporary torch-shadowOFF both reuse exact resulting Effect objects and add zero programs on subsequent driving. The temporary manual shadow override is restored explicitly. Vehicle controller retains its configured inactive shadow state by design; active memberships and the original material Effects are restored. Full driving GLB/physics/remote/network lifecycle and cancellation remain runtime integration checks, not covered by this bounded proof.
