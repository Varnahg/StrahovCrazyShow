# Projektový QA kandidát pořadí defines

Rozhodnutí rootu navazuje na same-engine proof manifest 96eb1c7cc96c2a97d3c6eccc03d6c82714dcf5401a3b6b234b959ff4a50af355. MaterialDefines.rebuild přebírá insertion order; isEqual porovnává key/value bez pořadí, zatímco Effect cache používá celý string. PBR/Standard ve stejném enginu vytvořily různé Effecty pro stejné finální hodnoty po různém pořadí prvního světelného stavu. Toto není atribuce B6 exit burstu: outside versus fresh-outside už bylo exact shodné.

Zvolený kandidát volá soukromý čistý canonicalResult až po dokončení původního toString. Nemění původní getter čtení, receiver/throw, _keys, rebuild, cloneTo, reset, isEqual, Effect cache nebo Game. Přenesen je přesný přijatý kontrakt: whole-block validace, nejvýše 32768 znaků/1024 defines, ordinal name sort a zachování původního spelling řádků/literálů. Každý neznámý řádek, reserved jméno, duplicate, expression, komentář, directive, netypický line terminator nebo nonfinite literal vrátí celý původní string byte-identicky. PBR numeric strings jsou zahrnuté. Parser hotového stringu nemůže poznat původ dvou platných řádků v jediné multiline property.

Plošné řazení _keys při rebuild bylo odmítnuto kvůli mutable stavu, pozdějším string/getter změnám a NodeMaterial přímému přidávání keys. Předdeklarace slotů mění needRebuild i rozsah dynamických properties. WebGPU-only cache key by ponechal původní shader text, ale potřebuje disjunktní raw/canonical namespace a kompatibilitu obou stran reuse. Přísný no-processCodeAfterIncludes guard by vyloučil i vestavěné PBR/Standard plugin cesty. Nová cache není potřebná. Zvolená serializace je menší projektový QA experiment, nikoli univerzální Babylon API oprava.

Negativní order-sensitive custom processor je skutečný limit: změnou pořadí může emitovat jiný shader. Syntax guard jej neumí odmítnout. Aktuální projektové pluginy v ověřené matici podle pořadí nerozhodují; deset větví prochází skutečným native WGSL processor/context, material hooks, instance výběrem, binding/draw a explicitním cleanup. Pipeline/submission je NullEngine, nikoli WebGPU driver. Srovnává se processed body po odstranění přesně zachyceného generated prefixu, prefixové řádky/hodnoty, celé public values, attributes/varyings/uniforms/samplers/binding metadata a plugin uniform data.

Runtime delta je jediný fyzicky kopírovaný Materials/materialDefines.js. Core i loaders jsou nové fyzické balíky; non-Babylon tools jsou jednotlivé readonly junctions. Zdrojové closure jsou kopie frozen V4 bez Game/stage/kamera/deadline změn. Původní patch je zachován byte-prefixem, nový hunk a šest hash substitucí v copied lockfile odpovídají skutečnému JS. Celý sedmisouborový patch byl reverzně odstraněn na vlastních touched-file kopiích a nově celý aplikován se shodnými výslednými bytes.

Cílený refaktoring soustředí původní WGSL scenario/engine do jednoho test fixture; original serializer body slouží jen jako read-only oracle, nikdy se neinstaluje na patched prototype. Pozitivní testy nepoužívají withCanonicalResult ani další canonicalizer. Přibyla kontrola extra native Effect reference/release. Žádný dlouhodobý runtime stav/cache/listener. Helper alokuje bounded Set/array/sort/string pouze při toString; výkon je nutné měřit ve skutečné hře.

Přenosové chyby jsou zachované: první aplikace JS String.replace interpretovala '$`' z regexp template jako replacement token, proto generátor přešel na callback replacement a parse gate; vadný soubor a log jsou archivované. Další cross-JSON baseline porovnání opomenulo, že JSON vynechává undefined properties; same-engine exact assertion zůstala a cross-artifact hodnoty se serializují shodně. Tyto chyby nejsou runtime baseline RED. Finální oddělený RED staging používá byte-identické final testy/fixture proti původnímu serializeru, žádné přepisování původních logů.

Mirrored car-fallback baseline z původního proofu zůstává nevyřešený RED a je archivovaný v accepted-proof/. Není opraven ani zahrnut jako passing canonical coverage. Existující širší wgsl-avatar-car LOD/mirrored/quality regrese nyní prochází; to není totéž jako onen specifický nevyřešený proof.

Root teprve sestaví plný define-order-v6 nad V4, provede plnou validaci a produkční startup/Golden/F/B6 inward/outward/exit bez detailního profileru. Časová úspora, menší počet produkčních modulů ani odstranění exit prodlevy se z tohoto CPU výsledku nevyvozují. V5 far-plane kandidát se nepřenáší.
