# Opaque ordering: isolated A/B decision

Source baseline205b4dda8028dd20b90dbd75177ba6ebd8d3fcf41d02cd97a8c44c42a6b9d05d. Only copied opaque-sort/art-lighting/test behavior may change. Played/native trees and pinned dependencies stay read-only. Root owns whole-game GPU A/B.

The existing steady profile is not a shader-compilation bottleneck:3812frames had19.536ms scene render,5.377ms active evaluation,12.735ms main draw and0shader creation;18periodic samples attributed10.128ms to bind/draw and2.233ms to preparation. These are CPU wall intervals, can include driver waits, and are not additive GPU time. End-of-benchmark draw inventories are not temporal averages.

Alternatives: strict near-to-far lowers overdraw but computes native-LOD/instance group distance and can interleave materials. Material-first maximizes a clear test of material binding locality and removes that distance work; it can increase overdraw and alter coplanar opaque outcomes. Coarse depth buckets compromise between both, but retain distance work and introduce an unmeasured bucket parameter. First experiment therefore uses only material-first, keeping sky-first and alpha/transparent/shadow queues unchanged. No new cache, query switch or quality change.

Pinned Babylon9.30 scene.isCachedMaterialInvalid compares material/effect/visibility. PBR mustRebind updates texture/plugin/material state; per-draw mesh/bones and unfrozen lights still run. No saved milliseconds are inferred. SubMesh.getMaterial(false) is NOT pure for MultiMaterial: it resets a pass draw cache when the effective child changes. MultiMaterial.getSubMaterial can also construct default material for out-of-range indices. New sorting reads renderingMesh.getMaterialForRenderPass(currentPass) and known native MultiMaterial.subMaterials directly. Unknown/custom or null/invalid child falls back to stable declared-container identity, without inventing an effective binding. No getLOD/readiness/transform access.

The original near-to-far factory stays available and its four actual-dispatch tests stay intact. The material-first factory creates just its comparator closure, no distance maps or observables. New tests compare actual baseline/candidate dispatch and binding, MultiMaterial/pass override/cache preservation, null material without allocation, actual LOD/instance dispatch, alpha/transparent/shadow queues, and repeated factory/dispose ownership. Output color/overdraw/performance acceptance requires the root's real production GPU comparison, including coplanar surfaces/depth offsets; NullEngine does not prove pixels or FPS.
