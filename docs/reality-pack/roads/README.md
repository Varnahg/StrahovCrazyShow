# Vaníčkova: source-calibrated fallback road footprint

The original IPR Prague orthophotos show a wider, locally curved carriageway
than the universal 7 m buffer around OSM way `124071290`. The mismatch occurs
at the stadium's south-east bend; it is not a reason to widen every secondary
road or move the PID coordinates.

The source images are the two unchanged 640 × 480 px IPR ImageServer exports
dated **8 June 2024**, with their original extent, attribution, request URL and
SHA-256 in `docs/photogrammetry/evidence/pid-149-vanickova-*-ortho-2024.json`.
These are 64 × 48 m reference areas at approximately 0.1 m/px. They are photo
interpretation, **not a land survey or photogrammetric height model**.

`vanickova-control-points.json` records every manually identified asphalt/kerb
edge pixel and an initial centreline guide. The final local axis is centred
between photo boundaries in perpendicular cross-sections, without consulting
PID coordinates. Guide endpoints at image crop boundaries remain fixed;
an image crop edge is not interpreted as a physical kerb. Boundaries follow the visible dark
asphalt transition, exclude the adjacent light stadium/turning aprons, and
include the marked edge/cycle lanes. Short portions obscured by cars are
interpolated from adjacent visible edges. Approximate boundary uncertainty is
0.3 m; individual kerb heights are unknown. No boundary was generated from a
GTFS buffer.

Run `scripts/calibrate-vanickova.py` with Blender's embedded Python. It uses the
existing `.cache/street-python` Shapely and pyproj packages, verifies image
checksums, transforms original image pixels through EPSG:3857 to the same
local world origin, and stages `.cache/vanickova-calibration-candidate.json`.
By default it does not write `shared/` or modify game data. Its explicit
`--publish` option publishes the source interpretation to
`shared/data/road-calibration.json`, separately from the raw OSM/PID sources.

The candidate contains the complete interpreted footprint, disjoint asphalt
additions, 14 short interpreted road-axis segments, provenance and a coverage
audit. Segment width comes from the perpendicular intersection with the
photographic footprint. The initial staging guides yielded approximately
7.46–12.52 m; the published, centred local segments yield **7.544–12.520 m**.
The old OSM feature and its explicit `class-inferred-not-measured` width remain
unchanged. The new interpreted segments have a separate IPR provenance.

## Integrated runtime result

`shared/data/road-calibration.json` is published and `scripts/fetch-streets.py`
now consumes its complete photo footprint. It subtracts the existing 25 mm
building mask and all non-asphalt material buckets before the final shared
union and partition. The generated street data has **380 unchanged OSM
features plus 14 separately attributed IPR road segments**. Their `nodeIds: []`
do not introduce pedestrian graph shortcuts. Within the traced footprint,
`nearestStreet(..., true)` uses the centred local photo axes; elsewhere it
keeps the original road query. It does not change the original OSM 7 m width.

Regeneration used only the existing cached OSM XML SHA-256
`7ff214452c91162fffc77809bd7c07f9511e694d2a7b48bc316d7b5865cedb62`.
It did not download OSM again, run `--ortho`, or modify the existing orthophoto
georeference/tree-crown reference.

`vanickova-integrated-audit.json` measures the **actual generated runtime
data with no candidate overlay**: 803/803 samples on asphalt and within their
road corridor, including 232 samples in the traced photo footprint.

The final generated footprint is 934.715 m²; its newly added asphalt is
464.482 m² before the established final simplification/export. The slight
difference from the historical staging delta comes from source millimetre
rounding and final partitioning. The entire generated network covers
99,219.54 m² and has zero building overlap.

Targeted verification passed **12/12 tests** across `streets.test.ts`,
`surface-transitions.test.ts` and `road-calibration.test.ts`. The original
own-polygon, upward-normal, building-mask, material-partition and quantization
assertions remain unchanged: 165,938 pavement triangles, one numerical
rounding sliver 1.1047 mm wide (within the existing 1.4142 mm coordinate
quantum), 432 continuous junctions and two documented building-apron cutouts.
The source correction adds two real material boundary segments: the exact
transition expectation was updated from 816 to **818**, with all transition
geometry checks passing and no tolerance changes.
`pnpm exec tsc --noEmit` also passed. Current source hashes and targeted test
results are recorded in `integrated-verification.json`.
