- Evidence: pinned AbstractEngine effect error observable carries effect/errors; WebGPUEngine restoration recreates a device and GPU resources but does not rerun application light preparation. The existing watcher only observes uncaptured device errors, so it cannot prove that asynchronous pipeline Promises succeeded. The actual A/B failure log also includes Promise rejection outside that channel.
- Decision: per-engine health owner with renderer ID, purpose and device generation; effect/device validation and context lifecycle observers, explicit `track` for owned async shader/pipeline work, `report` for resource/render failures, bounded first errors and unbounded counts. Do not attribute a global page rejection to one of several renderers. Shader/pipeline device-method profiling will supply the remaining explicit owned operations in KEY-31.
- A lost/restored device remains `restart-required` until the application creates a fresh engine. No false ready state after a resource-only restore. This deliberately supports the explicit exit/restart flow while preserving simulation authority; it does not claim transparent live recovery.
- Cache/lifecycle: no per-frame work, snapshot only when requested; closures are removed on engine/manual disposal, pending old-generation results cannot change the new generation, tracked rejection identity and success values are preserved. Diagnostic messages are limited to five retained records of 2000 characters, but every failure is counted/reported. External snapshot/callback mutation cannot change stored records.

Real NullEngine observables verify independent Game/preview attribution, loss/restore, teardown and other observer delivery. Fake deferred operations model timing/rejection; these tests do not open a GPU.
- Root Game integration: replaces separate effect/validation counters with one owner; texture failures feed health; preparation timeout invalidates health; readiness waits for a submitted frame; benchmark stores start/end generations and health validity, also requiring zero asset failures. Device loss stops rendering and clears held input with an exit/restart notice. Whole-frame GPU data remains distinct from future main-pass timings.
- Remaining: actual shader-module and async pipeline hooks, GPU errors, visible restart flow, first-frame readiness under pending compile, full build/test/integration and benchmark acceptance. KEY-30 is not Done. No worker/server/GPU process belongs to this unit.

## Startup continuation, submission gate and explicit device loss — second unit

Vlastník `webgpu-mig-01a14497-health2`, root `webgpu-migration-01a14497-root`; claim před zápisem, základ `5220f34`. Scope tvoří pouze health/validation, nový render-startup helper, jejich testy, tento handoff a vlastní health staging. Game/UI/factory ani hraný native-v3/4192 se nemění.

Rozhodnutí před implementací: `RenderHealth.guard<T>(ownedPromise)` oddělí čekání na vlastní životní cyklus od `track` metrik. Zachová hodnotu/rejection identity při platném ownerovi, při fault/dispose/generation loss odmítne okamžitě a odstraní waiter; nezruší podkladovou operaci, jejíž resource cleanup dál patří volajícímu. `waitForRenderStartup({engine,health,render,isReady,signal?,timeoutMs?},host?)` vlastní omezený on-demand RAF, begin/render/end, native validation scope a queue completion. Přijetí vyžaduje připravenost před i po submission, zdravou generaci a nulové pending operace. Visible-time limit kontroluje také synchronně před prací a před přijetím; hidden čas se nepočítá, AbortSignal a health fault mohou čekání ukončit i bez RAF.

Alternativní polling guardů byl odmítnut kvůli zpoždění a timerům; callbackové waitery vznikají jen při await. Pouhý engine onEndFrame neprokazuje dokončenou/validní native submission a nezachytí pozdní chybu. Trvalý render loop není potřebný; nový gate použije existující OnDemandRender a po dokončení nic neplánuje.

Primární Babylon 9.30: WebGPUEngine registruje device.lost pouze při vypnutém doNotHandleContextLost. Po testu isDisposed zavolá onContextLost observers, pak bez dalšího isDisposed testu spustí `_restoreEngineAfterContextLost`. Základní restore plánuje timer a nečeká na async initEngine před obnovou zdrojů. Disposal v callbacku tedy nezabrání již spuštěné auto-restore větvi. Vybrán vlastní konkrétní device.lost monitor a explicitní restart; root ve stejném checkpointu nastaví doNotHandleContextLost:true ve factory. Tento agent factory nemění. Native monitor musí oznámit i chybějící lost Promise; stávající WebGL observer zůstane, obě loss cesty se deduplikují v rámci generace.

Root převzal aktualizaci starého native fake-device v preview testu, který dosud nemá lost Promise; tato fixture cesta není součástí health scope. CPU regrese a konkrétní hashe budou doplněné před předáním. Žádný GPU/server/build/fullsuite/pnpm install.

Implementace druhého celku je hotová: `RenderHealth.guard` zachová původní rejection i v závodu s hlášením z `track`, uvolňuje waitery při settlement/fault/dispose/generation change a nepočítá je jako pending GPU operace. Loss v rámci jedné generace se započítá právě jednou, ať dorazí native Promise nebo Babylon observable; stará či disposed zařízení nepřepíšou nový stav. Chybějící native lost Promise je viditelná chyba schopnosti. Změna generace ani pozdní dokončení nemohou obnovit ready.

Nový `waitForRenderStartup` bere schválené options a volitelný testovací `RenderStartupHost`. Volající zastaví preload loop a předá skutečný render/readiness aktivní scény. Helper vlastní begin/end v jednom on-demand RAF a uzavře error scope i po výjimce. Přijetí vyžaduje readiness před i po skutečném odeslání, úspěšnou validation/queue completion a nulový počet health pending shader/pipeline operací. Queue completion se nevydává za kompilaci shaderů. Gate nezasahuje do vlastnictví engine/scene a po dokončení odpojí timer, visibility, abort a RAF; žádný trvalý readback/idle loop. WebGL nepřistupuje k native device. Nedostupná WebGPU submission validace není skrytý fallback.

Cílený refaktoring odstranil druhý dlouho žijící queue guard: při abortu a nikdy nedokončené queue by držel waiter navíc. Celý gate hlídá jeden outer guard. Synchronní `ensureActive` po await znovu ověřuje health phase, abort a visible-time deadline, protože již splněný Promise nemůže odvolat chyba doručená mezi settlement a continuation. Původní fault identity stále předá outer guard. Vlastní timeout/render/submission chyby se započítají jednou; abort není render fault. Hraný native-v3, závislosti a cizí Game/UI/factory WIP zůstaly mimo rozsah.
