## Přesná interpretace

- `createEffect` měří inclusive monotónní wall čas do return/throw. Návratový Effect se neprohlíží ani na then a nepřipojují se Promise handlery. Vnořené createEffect intervaly se mohou překrývat; součet není čas jediné souvislé sekvence instrukcí.
- WGSL úsek začíná vstupem initialize a končí návratem/výjimkou finalize se stejným contextem, processor instancí a generací. Jeden znovupoužitý microtask epoch marker na synchronní sérii místo jedné closure na shader označí překročení microtask hranice. U skutečné pinované Initialize→Process→Finalize cesty se async pokračování plánuje až po Initialize; tyto crossing úseky nejsou CPU, ale latency. Marker není univerzální instrumentace libovolného cizího JS scheduleru.
- Reentrance, překryté/recyklované pending contexty, nesoulad aktuálního processor contextu, chybějící třetí argument a invalid clocks se nevydávají za čistý CPU. Ambiguous bucket má prioritu před crossing bucketem; oba jsou latency/unknown a nepřičítají se do syncCpu. Nedokončené úseky jsou bounded a při zániku se evidují jako retired.
- Cold import čekání před Initialize je mimo WGSL úsek. Cold WGSL zpracování může začít až po návratu createEffect, tedy ne každý processing span je vnořený do nějakého measured createEffect callu. Čísla se nesmějí automaticky sčítat ani odečítat. Teplé native volání je typicky vnořené.
- Snapshot obsahuje jen fixed scope, createEffect metriky, WGSL syncCpu/crossedMicrotaskLatency/ambiguousLatency/pending/limit, counts a hook availability. Žádné shader texty/hashování/Effecty/context reference v reportu. Registry/pending map jsou pouze soukromé bounded pozorování.

## Ownership a lifecycle

- Hooky jen na daném engine a jeho konkrétním WGSL processoru, žádný globální prototype patch. Původní receiver, argumenty, návrat a exception identity se zachovají. Změna pozdějšího vlastníka zastaví vlastní diagnostiku; cleanup obnoví pouze dosud vlastní wrappery.
- Device/processor replacement, loss a restore mění explicitní generation/reason a retire pending. Countery zůstávají kumulativní; rozdílné generace nesmějí být porovnány jako jediný stejný device interval. Samotný dispose generaci nezvyšuje a countery nemaže. Již zahájené synchronous createEffect může dokončit účetnictví po nativním dispose ve stejné generaci; pozdější vstupy jsou no-op diagnostiky.
- Observer/clock/cleanup chyby se čítají a nepřebijí native výjimku. Constructor má explicitní rollback částečně instalovaných hooků také při chybě před připojením dispose observeru. Veřejné Observable.remove je záměrně deferred, aby cleanup ve stejné nativní notifikaci nepřeskočil jiné observers.
- Pozorování callbacků nevyžaduje engine rendering ani pravidelný RAF. Microtask marker po dispose nepřispěje do metrics a nedrží jednotlivé shader contexty; jediné krátké marker closure je zahozené při nejbližším checkpointu.
