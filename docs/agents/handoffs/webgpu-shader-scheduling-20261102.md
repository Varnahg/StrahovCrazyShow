## API a lifecycle

- `new WebGpuShaderPreparation(engine, { signal?, requestFrame?, cancelFrame?, now?, budgetMs=4, maxPerFrame=4, maxQueued=1024, onError? })`.
- `isReady(): boolean` vyhazuje zachovaný terminální fault, jinak čeká na vyprázdnění FIFO a settlement skutečně spuštěné práce, také po očekávaném retirement. `snapshot()` pouze kopíruje bounded čísla a stav; nevyvolává readiness ani další práci. `dispose()` je idempotentní.
- Snapshot: active/inert/disposed/faulted, queued/pending/started/completed/cancelled/passthrough/frameCount/workCpuCount/workCpuMs/workCpuMaxMs. Žádné shader source/name strings. CPU metriky zachycují synchronní část skutečných queued native volání; passthrough je uveden zvlášť. Čítače saturují.
- Instalovat po CompilationProfile: jeho existující wrapper zůstává uvnitř a počítá práci až při skutečném dispatch. Root drží pokrytí přípravy kvalit i finálního submitted-frame gate a disposuje queue před pipeline adaptérem.
- Rozpočet4ms rozhoduje, zda zahájit další nativní call; jeden call se nepřerušuje a může limit výrazně překročit. Počet i CPU budget omezují FIFO dávku; práce přidaná callbackem zachovává pořadí a další RAF se neplánuje reentrantně. Outstanding limit zahrnuje běžící/retired native práce, ne jen čekající pole.
- `_deletePipelineContext` je nutné sledovat: skutečný WebGPU Effect.dispose/_releaseEffect jde touto cestou, ale resetCachedPipeline bez WebGL contextu nic nemaže. Přímé context.dispose zase nemá disposed marker. Helper sleduje obě skutečné metody pouze u vlastních čekajících kontextů; neprochází registry/scény a nedělá nové ownership rozhodnutí za Effect. Očekávaný retirement ruší job/callback bez shader error a deleguje původní cleanup.
- Abort/dispose/device loss/replacement zastaví frontu a potlačí pozdní queued onReady; vlastní Promise rejection je vždy obsloužená, i když ji Babylon zahodí. Helper neeviktuje Effecty ani preventivně neničí jejich contexty. Už spuštěnou native async práci nelze odvolat, její dokončení se zúčtuje a stale callback se nepropustí.
- Jediný owner na engine; nezávislé contexty sdílejí jeho FIFO. Metody se obnovují jen pokud stále patří tomuto wrapperu; pozdější vlastník se nepřepíše. WebGL je inertní a výchozí RAF funkce se hledají až při skutečném použití, takže inertní konstrukce funguje v Node bez browser globals. Detachable engine dispose/lost/restored observables nezavádějí permanentní device.lost Promise closure.
