## Čtyři rozumné varianty (návrh, ne produktový benchmark)

| Varianta | Kdy je vhodná | Co zůstává editovatelné / cena iterace | Riziko a ruční práce |
| --- | --- | --- | --- |
| **A. LLM → uložený `bpy` skript** | Stylizované rekvizity, fantastické stroje, dveře, skládací či létající díly; přesné rozměry a pohyb | Parametry, pojmenované části, materiály, vlastní klíče/Actions. Uložený skript a specifikace dávají auditovatelný opakovatelný vstup. | **B. LLM ↔ live MCP ↔ Blender** | Postupné textové změny již existující scény a kontrola více úhlů / animačních snímků | Stejný nativní obsah jako A, doplněný o iterativní pozorování. | **C. | **D. **Volba pro první levný pilot: A**, následně B pro pohodlnou iteraci, pokud uspěje export a potřeba živé zpětné vazby se potvrdí. A minimalizuje počet částí řetězce a umožní porovnat opakování téhož vstupu. Pro krásný organický hero asset je D kandidát, ne již ověřený vítěz. Žádný čtený zdroj nedokládá, že jeden model řeší libovolnou geometrii, rig i textovou animaci bez čištění.

## Volba reprezentace podle objektu

Toto je doporučení odvozené z kontraktů S11, S14–S16, nikoli výsledek měření:

- **Pevný celek / pohybující se rekvizita:** vlastní transformace objektu. **Více pevných dílů:** pojmenovaná hierarchie a správné pivoty, jednotlivé klipy; např. kryt a vrtule mají samostatné uzly. Není nutný humanoidní model pohybu.
- **Kloubový nehumanoidní tvor / mechanický rig:** vlastní skelet s definovanými osami a váhami; text specifikuje fáze/pózy, LLM je zapíše jako klíče. Anatomie, kontakt se zemí a váhy se musí vizuálně ověřit. Humanoidní retarget nelze prohlásit za obecné řešení.
- **Měkký předmět, rostlina, obličej, nafukování:** omezené pojmenované shape keys, případně skelet. Konstantní mapování vrcholů musí přežít export; topologicky odlišné generované objekty nejsou hotové morph cíle.
- **Kapalina, trhání, částice nebo měnící se topologie:** zachovat autorovací simulační řešení v `.blend`; core glTF není přenositelný obecný simulátor. Alternativní runtime efekt vyžaduje vlastní návrh a měření.

## Iterace bez ničení starší práce

Navržený kontrakt zadání pro LLM: identifikátor assetu, metry/osy, názvy jednotlivých dílů a pivotů, oddělené materiály, FPS/délka klipu, počáteční/konečná póza, kontakt, smyčka a zakázané změny ostatních klipů. Namísto promptu „udělej to hezčí“ měnit jeden pozorovatelný parametr: „zachovej `idle`, vytvoř nový `open_v2`; kryt se otevře o 70° za 0,6 s a dosedne bez překmitu“.

Založit vlastní collection, stabilní jména/ID a samostatné parametrické vstupy; aktualizovat cílené datablocky. Nedestruktivnost musí zajistit skript, MCP ji neslibuje. Změna existující Action musí respektovat její sloty; nové klipy uchovat samostatně a testovat, že se staré neztratily. API 5.2 pro přímou práci s F-Curve nabízí následující doložený podpis (nebyl zde spuštěn):

```python
action.fcurve_ensure_for_datablock(obj, "location", index=2)
```

Předpoklad je již přiřazená Action. Přenos tohoto konkrétního volání na Blender 4.5 zde nebyl doložen; použít dokumentaci připnuté verze. Vyšší API `keyframe_insert` z r1 je jednodušší pilotní základ. [S14](https://docs.blender.org/api/5.2/bpy.types.Action.html)

Pro reprodukci uložit text zadání, vytvořený skript, parametry a náhodné seed hodnoty, přesný build Blenderu, addon/server verze + hash, jména Actions, FPS/rozsahy, export preset, verzi exportéru a hash vstupů/výstupů. Uchovat `.blend` **před** bake/redukčním exportem. Stejný prompt bez stejného výsledného kódu není deterministická reprodukce (návrh pilotní metodiky).

## Co konkrétně znamená local / cloud / licence

Blender samotný je zdarma a provozovatelný offline; cloudový LLM nebo externí 3D API je další služba s vlastními podmínkami/cenou. Čistá A nepotřebuje MCP. U B vypnutí telemetrie neznamená nulovou síť: v již čteném `addon.py` je GUI startup check na GitHub, blokovaný proměnnou `BLENDERMCP_NO_UPDATE_CHECK`; asset/generační integrace také mají síťové cesty. Z toho plyne, že tvrzení „plně lokální“ vyžaduje konkrétní konfiguraci i pozorování provozu. [S13](https://www.blender.org/about/license/), [r1/S2](https://raw.githubusercontent.com/ahujasid/mcp-for-blender/main/addon.py)

MIT licence repozitáře není totéž co licence uměleckého výstupu, LLM nebo zakoupeného assetu; případná distribuce addonů se musí posuzovat i podle publikovaných pravidel Blender Foundation. V tomto průzkumu nebyly ověřeny tarifní částky žádného LLM ani Premium, a proto neuvádím falešnou cenu za asset. [S13](https://www.blender.org/about/license/), r1/S3–S4.

## Reprodukovatelný pilot a runtime přejímka (pouze návrh)

1. **Připnout stabilní verzi:** kandidáti r1/S8 jsou 5.2.2/4.5.14. Zvolit jeden a zaznamenat build hash; 5.3 Beta a 5.2.3 RC z 20. 10. není důvod přepsat stable profil. Ověřit nainstalovanou verzi až v samostatně rezervovaném pilotu. Pro MCP získat `get_addon_status`; minimum 3.0 z README není test matice.
2. **Tři různé úlohy:** (a) originální létající schránka s víkem/rotorem, (b) nehumanoid se čtyřmi kloubovými končetinami, (c) měkký svítící tvor s pojmenovaným nafouknutím. Vlastní fikční design a stejné textové požadavky pro opakování; ne adaptace chráněné postavy. Vytvořit `.blend`, skript, statický náhled z více stran a krátký strip každého klipu.
3. **Dvě aditivní revize:** změnit tempo jednoho klipu a přidat druhý; doložit zachování původní geometrie, materiálů a prvního klipu. Otevřít uložený `.blend` znovu a editovat klíč ručně. Tím se ověří editovatelnost, kterou video ani screenshot nedokládá.
4. **GLB přejímka:** export s explicitním profilem, validace a nový import do prázdného Blenderu i cílového enginu. Porovnat počty/názvy/délky klipů, root motion, pivoty, rest pose, deformace, materiály a textury. FBX může být separátní výstup, ale jeho export/retarget vlastnosti zde nebyly čteny ani ověřeny. Základní smlouva GLB je doložena S11 a r1/S5; úspěch pilotu nikoli.
   Pro jeden souvislý klip víceobjektových transformací popisuje již čtený manuál 5.2 režim **Animation → Mode → Scene** s volbou jednoho klipu (nikoli rozdělení po objektech). Pouhý shodný název několika Actions neznamená jejich sloučení. Přesný Python enum/parametr export operátoru zde nebyl čten; v pilotu zjistit RNA konkrétní nainstalované 5.2 a zaznamenat hodnoty. Režim Scene není důkazem zachování všech materiálových či simulačních animací. [r1/S5](https://docs.blender.org/manual/en/5.2/addons/scene_gltf2.html)
5. **Náklady a estetika:** měřit počet oprav promptu/kódu, lidské minuty čištění, GPU/CPU čas, tokeny a skutečnou cenu; vedle technické validity samostatně přijmout siluetu, čitelnost, barevnost a pohyb. „Hezký“ není číslo ze zdrojového README.
6. **Runtime rozpočet nastavit z měření:** reportovat exportované trojúhelníky/vrcholy, materiálové primitives, textury/VRAM, kosti, vlivy, morph targets, velikost klipů a draw calls, počty souběžných assetů. Porovnat plnou hru se/bez assetu na cílové kvalitě a GPU, uvést p95/p99 i animované scény. Nepoužívat univerzální polygonový limit jako výsledek tohoto výzkumu. Cleanup: odstranit skryté/duplicitní části, snížit nepotřebné materiály a klíče, zvolit LOD a kolize; každý zásah znovu vizuálně ověřit.

## Hranice a stop pravidlo

Coverage dosaženo: mechanismus text→bpy, live pozorování, procedurální větev, nativní save, Actions/slots, nehumanoid/pevné/deformující objekty, glTF kontrakt nezávislého vydavatele, privacy a konkrétní spuštěcí cesty. Další produktový search by teď nepřinesl exportní důkaz; dvě kola ukončena.

**Hledáno, ale neprokázáno:** aktuální úspěšný MCP benchmark na 4.5/5.2, libovolná krásná organická geometrie čistým prompt→bpy, spolehlivý text→rig bez ruční práce, podporovaný přenos živých GN simulací do GLB, obecná exportovatelnost všech driverů a deformací, nulové síťové požadavky s vypnutou telemetrií, ceny konkrétního LLM a end-to-end výkon. Vyhledávány oficiální Blender/glTF a původní MCP repo; třetí strany, Reddit, galerie, neoficiální mirrors a další README opisující tutéž implementaci nebyly nezávislou evidencí.

Dodatečný integrační dotaz po dosažení limitu 8 zdrojů limitu: **FBX vertex/shape-key export nebyl ověřen**. Volání `export_scene.fbx` ani `bake_anim=True` nelze samo považovat za důkaz, že vertex deformace přežije FBX roundtrip; koordinátor dostal tuto mezeru k samostatnému čtení oficiálního FBX kontraktu. Tento digest nedělá závěr o konkrétním AnimateAnyMesh exportu, jehož soubor zde nebyl čten.

Části identity jsou aktuální živé stránky, ne neměnný release. `source-access.json` zachycuje SHA256 staženého textu bez archivování plných cizích dokumentů. Žádné dlouhé přímé citace; rozsah parafrází jednotlivého zdroje zůstává omezený. K praktickému tvrzení „funguje“ je stále nutné rezervované pilotní ověření.
